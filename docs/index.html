Capabilities / 01

Simple controls for the commands that carry real risk.

Keep ordinary diagnostics fast. Add friction only when the target, resource, reach, or blast radius warrants it.

01 · CONTAIN

Keep secrets out of agent context

Block configured resources—including reads—before kubectl prints them. With secret protected, direct Secret access and uninspectable --raw requests are refused.

SETUPkubectl-guard config add-resource secret
02 · APPROVE

Pause production changes

Gate by context, namespace, or resolved API server. Agent approval requires explicit enrollment, fresh OS authentication, and one exact execution. Passwordless sudo fails closed.

SETUPkubectl-guard config add-context 'prod-*'
kubectl-guard config confirm-mode agent-relay
kubectl-guard approval setup
03 · REACH

Control access vectors

Gate or block exec, cp, attach, debug, port-forward, and proxy on every context.

YAMLsensitive_access: gate
04 · SCOPE

Catch wide commands

Detect bulk selectors, --all, all namespaces, force deletes, zero grace periods, and apply --prune.

SETUPkubectl-guard config blast-radius gate
05 · INSPECT

Preview before approval

Show a diff for apply-style changes or list affected objects for destructive commands. Genuine dry runs avoid noisy prompts.

YAMLpreview_before_confirm: true
06 · FREEZE

Switch to read-only

Freeze mutations everywhere while allowing known-safe reads. Unclassified plugin verbs fail closed during a freeze.

RUNkubectl-guard freeze
07 · INTERCEPT

Catch kubectl calls from agent subprocesses

The PATH-shadowing shim intercepts calls made by name—even in non-interactive shells where aliases do not apply. doctor --require-interception verifies the route.

SETUPmake install-shim
kubectl-guard doctor --require-interception
08 · EXPLAIN

Preflight without executing

explain --json -- … returns the real policy decision without running kubectl, prompting, or writing an audit entry.

RUNkubectl-guard explain --json -- delete pod api
Approval relay / 02

Human approval that works inside an agent workflow.

No brittle terminal scraping. The guard returns a stable signal the agent can understand and relay.

1. Guard interrupts

A gated command returns structured JSON on stderr and exits with code 4. Nothing reaches the cluster.

2. Agent asks

The agent surfaces the exact command, context, and approval prompt in its own interface.

3. Human authenticates

The human runs kubectl-guard approve. OS authentication succeeds, the request is consumed, and that exact command executes once.

{"decision":"needs-confirmation","reason":"authenticated-approval-required","context":"prod-cluster","command":"delete pod api","prompt":"Approve once: kubectl-guard approve A1B2C3D4E5F6 -- kubectl delete pod api"}
Comparison / 03

One layer cannot solve every Kubernetes access problem.

kubectl-guard covers the local, agent-command layer. RBAC and admission policy remain the server-side foundation.

For teams / 04

Built for a shared corporate safety posture.

Central teams can set a floor while developers keep a familiar kubectl workflow.

POLICY FLOOR

Enforced system baseline

An administrator-owned config merges beneath user policy. Most restrictive wins, and enforced mode disables config, audit, and bypass environment escape hatches.

ATTRIBUTION

Actor-aware controls

Record both the OS user and the driving actor. Apply stricter context or namespace modes to labels such as an agent or CI runner.

AUDIT

Tamper-evident history

Concurrent-safe JSONL logging, optional HMAC chaining and verification, rotation, webhook delivery, and syslog shipping.

CHANGE CONTROL

Guard the guard

Configuration changes are audited before they take effect. Weakening changes can require confirmation; strict permissions fail closed on writable policy files.

SUPPLY CHAIN

Verifiable releases

Release artifacts include keyless cosign signatures, SLSA provenance, checksums, and per-archive SPDX JSON SBOMs.

OPERATIONS

Health checks and headless setup

doctor --json checks interception, configuration, permissions, audit writability, kubectl reachability, and target resolution. Headless bootstrap denies mutations by default.

Low operational footprint. A standalone Go binary for macOS and Linux, configured locally with YAML. No admission webhook, controller, sidecar, or cluster-wide installation is required.

Know the boundary.

kubectl-guard is a client-side guardrail for cooperative agents and accidental commands—not a replacement for RBAC. The shim intercepts ordinary kubectl calls by name, but a process with access to credentials can use an absolute binary path or another API client. Use least-privilege RBAC for hard enforcement.
